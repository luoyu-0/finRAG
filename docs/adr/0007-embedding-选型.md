# ADR-0007 Embedding 选型

- **状态**：已接受
- **日期**：2026-10-12
- **决策者**：项目组
- **相关**：[系统架构](../architecture/系统架构.md) · [开发分工](../开发分工.md) · [术语表](../../GLOSSARY.md)

## 背景

向量检索需要选择适合中文金融制度材料的 Embedding 模型。当前阶段优先验证完整链路，本地开发环境没有专用推理服务器，模型体积与 CPU 推理成本需要保持可控。

## 决策

- 初始使用 `BAAI/bge-small-zh-v1.5`（512 维），平衡中文检索效果与本地部署成本。
- Embedding 通过 Provider 接口接入，业务代码不直接依赖模型实现。
- 获得正式数据后，以固定评测集比较检索效果，再决定是否替换模型。

## 考虑的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 更大规模的中文 Embedding 模型 | 初期资源消耗更高，且目前没有正式数据证明能带来足够收益。 |
| 远程 Embedding API | 引入额外网络、成本与数据合规依赖，不利于本地离线处理制度材料。 |

## 后果

**正面**

- 模型较轻，普通开发电脑可以承担初期向量生成与检索验证。
- Provider 隔离使后续替换模型无需修改 RAG 核心流程。

**负面**

- 512 维向量会成为 Milvus Collection Schema 的一部分，替换不同维度模型时需要重建向量索引。
- 当前选型尚未经过真实制度数据评测，不能视为最终效果最优模型。
