# ADR-0006 选择性 OCR 路由

- **状态**：已接受
- **日期**：2026-10-12
- **决策者**：项目组
- **相关**：[系统架构](../architecture/系统架构.md) · [开发分工](../开发分工.md) · [术语表](../../GLOSSARY.md)

## 背景

命题要求支持文本、PDF 和图片，其中既有带文本层的文本型 PDF，也有纯扫描件。对所有 PDF 全量执行 OCR 会浪费算力，还可能用识别结果替换原本正确的文本。

## 决策

- 采取**选择性 OCR 路由**：`原生文本提取优先 → 逐页质量判断 → 不合格页面才进入 OCR`。
- 判断依据包括有效字符数、乱码比例、文字覆盖率、阅读顺序、图片占比与表格完整性。
- OCR 以 **PaddleOCR 为主**、**Tesseract 为备用与对照基线**。
- OCR、版面分析与 Embedding 属于**离线 Worker 任务**，与在线问答路径隔离并限制并发。

## 考虑的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 对所有 PDF 全量 OCR | 对带文本层的 PDF 是无效计算，且会把原本正确的文本替换成可能出错的 OCR 结果。 |
| 让视觉大模型直接读 PDF | 无法替代稳定分页、条文切分、版本管理、增量索引与来源定位，只适合作为复杂版面的补充复核。 |
| OCR 与在线问答共用执行资源 | 导入任务会挤占在线问答资源，影响响应时间。 |

## 后果

**正面**

- 避免对文本型 PDF 做无谓 OCR，减少算力消耗和识别错误。
- 离线任务与在线路径隔离，在线响应时间不被导入任务挤占。

**负面**

- 页面质量判断的阈值必须依据真实制度材料确定，目前无法给出具体数值。
- 需要分别维护原生文本提取、质量判断和 OCR 处理链路。

**待办**

- 获得样本数据后确定质量判断阈值。
- 评估文本可用率、OCR 字符错误率、条文边界、表格结构、引用定位、单页耗时与峰值内存。
- 比较 PP-OCR、PP-Structure 与 PaddleOCR-VL 在中文制度材料上的效果和资源消耗。
