# ADR-0004 向量库选型

- **状态**：已接受
- **日期**：2026-10-12
- **决策者**：项目组
- **相关**：[系统架构](../architecture/系统架构.md) · [容器架构说明](../architecture/系统架构.md) · [术语表](../../GLOSSARY.md)

## 背景

混合检索需要保存制度分块的向量并在查询时检索。项目还要求持久化数据、支持多进程访问，并通过 Docker Compose 在 Windows 11 和 Linux 间保持一致部署。

## 决策

- 使用 **Milvus Standalone**，配合 `etcd`（元数据）与 `MinIO`（对象数据），随 Docker Compose 一并启动。
- MySQL 保存业务状态与元数据，Milvus 保存向量及检索所需字段，两者通过稳定 ID 关联。

## 考虑的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| FAISS（命题参考资料中提及） | 缺少服务化的持久化与并发访问能力；项目需要多进程访问与持久化，选择服务化的 Milvus。 |

## 后果

**正面**

- 检索能力完整，支持关键词与向量双通道。
- 服务化存储支持持久化与多个应用进程访问。

**负面**

- Milvus Standalone 按官方要求需要 Docker Desktop 至少分配 **8 GB 内存**，提高了本地开发与演示的机器门槛（已通过 `.wslconfig` 分配 12 GiB 应对）。
- 增加了 Compose 的服务数量（6 个），启动与排障复杂度上升。
