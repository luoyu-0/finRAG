# ADR-0005 本地开发环境与资源上限

- **状态**：已接受
- **日期**：2026-10-12
- **决策者**：开发 C
- **相关**：[系统架构](../architecture/系统架构.md) · [容器化部署验收记录](../testing/容器验收记录.md) · [术语表](../../GLOSSARY.md)

## 背景

主要开发与演示环境是**普通 Windows 11 家庭版个人电脑**。三个约束同时存在：

1. 家庭版**没有 Hyper-V**，而 Docker Desktop 需要虚拟化后端；
2. Milvus Standalone 需要至少 **8 GB** 可用内存（见 [ADR-0004](0004-向量库选型.md)）；
3. 容器配置必须能迁移到 Linux 服务器，以便后续部署到评测方提供的环境。

## 决策

1. 使用 **WSL2** 承载 Docker Desktop，采用 **WSL 2 后端**。
2. WSL 虚拟机的 CPU 与内存上限通过 `%UserProfile%\.wslconfig` 设定：`memory=12GB`、`processors=6`、`swap=4GB`。
3. 跨环境约束：Dockerfile 与 Compose **不使用 Windows 盘符或宿主机绝对路径**；配置经环境变量注入；使用命名卷与健康检查；宿主机端口默认只绑定 `127.0.0.1`。

## 考虑的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| Docker Desktop 的 Hyper-V 后端 | Windows 家庭版不提供 Hyper-V。 |
| 沿用 WSL2 默认资源（物理内存的 50%） | 与 Milvus 的 8 GB 需求叠加后，留给 Windows 主机的余量过小，容易导致 Milvus 反复重启。 |
| 在宿主机直接安装 MySQL、Milvus、PaddleOCR | 与「新成员不必单独安装数据库与 OCR 工具」的目标冲突，且无法保证跨环境一致。 |

## 后果

**正面**

- 家庭版可用，无需额外系统授权。
- 镜像、环境变量、命名卷与健康检查结构均可迁移到 Linux。

**负面与经验教训**

以下三点是配置过程中实际踩到的，记录以免重复：

1. **Docker Desktop 的 Resources 面板不决定虚拟机资源。** 使用 WSL 2 后端时，CPU 与内存上限**只能**通过 `.wslconfig` 控制。
2. **`.wslconfig` 仅在 WSL 虚拟机启动时读取一次。** 若虚拟机一直存活（例如首次初始化阶段打开的发行版窗口），配置不会生效。必须先 `wsl --shutdown`，并确认 `wsl -l --running` 显示无运行实例后再启动。
3. **判断配置是否生效应看 `nproc`，而不是 `free -h`。** 配置未生效时的默认值是物理内存的 50%，与 12 GB 设定值接近，`free -h` 无法区分；而 `nproc` 在 `processors=6` 生效时为 6、未生效时为逻辑核心总数，判据明确。
