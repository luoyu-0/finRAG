# ADR-0002 前端代码检查使用 oxlint 而非 ESLint

- **状态**：已接受
- **日期**：2026-10-12
- **决策者**：开发 C
- **相关**：[系统架构](../architecture/系统架构.md) · [README](../../README.md) · [术语表](../../GLOSSARY.md)

## 背景

前端在引入代码检查时发现，业界默认方案 **ESLint + typescript-eslint 无法用于本项目**：

1. **peer 依赖冲突。** 项目锁定 `typescript@7.0.2`，而 `typescript-eslint@8.71.1` 与 `@typescript-eslint/parser@8.71.1` 的 peer 要求为 `typescript >=4.8.4 <6.1.0`。
2. **ESLint 默认解析器完全无法解析 TypeScript。** 实测 `eslint src/App.tsx` 直接报错：

   ```
   3:5  error  Parsing error: Unexpected token <
   ```

   也就是说，在不引入 TypeScript 解析器的前提下，ESLint 对本项目的前端代码**不具备任何检查能力**。

## 决策

使用 **oxlint** 承担 TS/TSX 代码检查，**Prettier** 承担格式化，**不引入 ESLint**。

原因：oxlint 自带解析器，不依赖 `typescript` 包，因此不受 TypeScript 版本约束。

## 考虑的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| ESLint + 通过 `--legacy-peer-deps` 强行安装 typescript-eslint | 官方未声明支持 TypeScript 7，规则可能报错或静默失效；且会使 `npm ci` 在 CI 中同样需要该标志，降低构建可复现性。 |
| 将 TypeScript 降级到 `<6.1` | 为工具链让路而降低语言版本，会影响 `vite` 与 `@vitejs/plugin-react` 的既有组合，代价与收益不成比例。 |
| Biome（检查与格式化一体） | 技术可行，但会同时替换掉 Prettier，改动面更大，且团队已有 Prettier 使用习惯。 |

## 后果

**正面**

- 检查工具不受 TypeScript 版本限制，后续升级 TypeScript 不会再次触发同类问题。
- 不引入 ESLint 及其插件树，前端依赖显著精简（对比：移除 ESLint 相关包后减少了 111 个依赖）。
- 执行速度快，适合在 CI 与提交前频繁运行。

**负面**

- 规则集与 `eslint-plugin-react-hooks` **不完全等价**，React Hooks 相关的部分检查能力弱于 ESLint 生态。
- 团队需要适应新工具与其配置格式（`.oxlintrc.json`）。
- 生态插件少于 ESLint；若后续需要某个 ESLint 专有插件，可能需要重新评估。

**配套说明**

类型正确性**不**由 lint 承担，而是由 `tsc --noEmit`（`tsconfig.json` 与 `tsconfig.node.json` 两份配置）在 `npm run build` 与 CI 中保证。两者分工不重叠。
