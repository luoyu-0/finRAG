# 系统接口

本文档集中维护当前已实现接口和计划中的核心契约。除健康检查、登录、注册和刷新会话外，业务接口默认要求鉴权；新增业务接口时必须标明允许角色和资源归属规则。

## 1 通用约定

- API 统一位于 `/api/v1`。
- JSON 字段使用 `snake_case`，时间使用带时区的 ISO 8601 字符串并按 UTC 保存。
- Access Token 通过 `Authorization: Bearer <token>` 发送。
- Refresh Token 通过 `HttpOnly` Cookie 传递，不进入 JSON 响应或浏览器存储。
- `401 Unauthorized` 表示未登录、凭据无效或会话过期；`403 Forbidden` 表示身份有效但权限不足。
- 错误至少包含稳定的 `error_code` 和可读 `message`，不得返回密码、Token、Cookie 或异常堆栈。

错误示例：

```json
{
  "error_code": "AUTH_INVALID_CREDENTIALS",
  "message": "用户名或密码错误"
}
```

### 1.1 分页

所有列表接口统一使用下列查询参数与响应包装。

查询参数：

| 参数 | 类型 | 默认 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| `page` | 整数 | `1` | ≥ 1 | 从 1 开始的页码 |
| `page_size` | 整数 | `20` | 1–100 | 每页条数 |

响应包装：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0,
  "has_next": false
}
```

`total` 为满足筛选条件的总条数，`has_next` 等价于 `page * page_size < total`，供前端决定是否继续加载。

非列表接口**直接返回资源对象**，不额外包一层 `data`，与既有鉴权、用户与问答接口保持一致。

### 1.2 角色与归属

- 角色只有 `admin` 与 `user`。
- 标注「本人」的接口只能访问当前登录用户自己的数据，越权访问返回 `403 AUTH_FORBIDDEN`。
- 权限必须由后端执行；前端的路由守卫与按钮隐藏只是交互优化，不构成授权控制。

## 2 后端健康检查

- 方法：`GET`
- 路径：`/api/v1/health`
- 鉴权：无
- 状态：已实现

成功响应：

```json
{
  "status": "ok",
  "service": "backend"
}
```

该接口只表示 FastAPI 进程可以响应，不代表 MySQL、Milvus、DeepSeek 或 OCR 已通过业务级检查。深度健康检查应使用独立接口，避免改变本接口的轻量语义。

## 3 鉴权接口

登录、注册、刷新、退出已实现；修改密码仍为草案。Refresh Cookie 名为 `finrag_refresh`，作用路径为 `/api/v1/auth`，具有 `HttpOnly` 与 `SameSite=Lax` 属性；正式环境还需 `Secure`。

### 3.1 登录

- 方法：`POST`
- 路径：`/api/v1/auth/login`
- 鉴权：无

请求：

```json
{
  "username": "demo_user",
  "password": "用户输入的密码"
}
```

成功响应：

```json
{
  "access_token": "短时访问令牌",
  "token_type": "bearer",
  "expires_in": 900,
  "user": {
    "id": "用户 ID",
    "username": "demo_user",
    "display_name": "演示用户",
    "role": "user",
    "status": "active"
  }
}
```

响应同时设置 Refresh Cookie。用户名不存在、密码错误、账户禁用或锁定时返回统一登录失败信息。

### 3.2 注册

- 方法：`POST`
- 路径：`/api/v1/auth/register`
- 鉴权：无
- 仅要求用户名和密码非空，用户名最多 64 字符。请求示例：

```json
{"username":"new_user","password":"自设密码"}
```

- 成功：`201`，设置 Refresh Cookie；新账户固定为 `user`、`active`，注册后直接登录。响应示例：

```json
{
  "access_token": "短时访问令牌",
  "token_type": "bearer",
  "expires_in": 900,
  "user": {
    "id": "用户 ID",
    "username": "new_user",
    "display_name": "new_user",
    "role": "user",
    "status": "active"
  }
}
```
- 用户名重复：`409 AUTH_USERNAME_EXISTS`；缺少字段或用户名为空：`422 VALIDATION_ERROR`。

### 3.3 刷新会话

- 方法：`POST`
- 路径：`/api/v1/auth/refresh`
- 鉴权：Refresh Cookie

成功时轮换 Refresh Token 并返回新的 Access Token。Refresh Token 缺失、过期、已撤销或重复使用时返回 `401`，必要时撤销同一 Token 家族。

成功响应：`{"access_token":"短时访问令牌","token_type":"bearer","expires_in":900}`。并设置新的 Refresh Cookie；前端对并发的刷新请求只发起一次换票。

### 3.4 退出登录

- 方法：`POST`
- 路径：`/api/v1/auth/logout`
- 鉴权：Access Token 或 Refresh Cookie

撤销当前 Refresh Session 并清除 Cookie。接口保持幂等，重复退出不返回内部错误。
成功返回 `204`，响应无 JSON 正文。

### 3.5 修改密码

- 方法：`POST`
- 路径：`/api/v1/auth/change-password`
- 鉴权：`user`、`admin`

请求：

```json
{
  "current_password": "当前密码",
  "new_password": "新密码"
}
```

修改成功后撤销该用户的其他 Refresh Session。

## 4 用户接口草案

### 4.1 获取当前用户

- 方法：`GET`
- 路径：`/api/v1/users/me`
- 鉴权：`user`、`admin`
- 状态：已实现

返回当前用户的 ID、用户名、展示名称、角色和状态，不返回密码哈希或会话 Token。

成功响应示例：

```json
{"id":"用户 ID","username":"demo_user","display_name":"演示用户","role":"user","status":"active"}
```

### 4.2 修改当前用户

- 方法：`PATCH`
- 路径：`/api/v1/users/me`
- 鉴权：`user`、`admin`

第一阶段只允许修改 `display_name`，用户名和角色由管理员接口维护。

### 4.3 创建用户

- 方法：`POST`
- 路径：`/api/v1/users`
- 鉴权：`admin`

请求包含 `username`、初始密码、`display_name` 和 `role`。日志和响应不得回显初始密码。

### 4.4 用户列表

- 方法：`GET`
- 路径：`/api/v1/users`
- 鉴权：`admin`

支持分页，并可按用户名、角色和状态筛选。

### 4.5 更新用户

- 方法：`PATCH`
- 路径：`/api/v1/users/{user_id}`
- 鉴权：`admin`

允许修改展示名称、角色和状态。禁用用户后立即撤销其 Refresh Session；不得通过普通流程禁用系统中最后一个可用管理员。

### 4.6 撤销用户会话

- 方法：`DELETE`
- 路径：`/api/v1/users/{user_id}/sessions`
- 鉴权：`admin`

撤销指定用户全部 Refresh Session，用于账户异常、密码重置或权限变更后的强制退出。

## 5 鉴权错误码

| 错误码 | HTTP 状态 | 含义 |
| --- | ---: | --- |
| `AUTH_INVALID_CREDENTIALS` | 401 | 登录凭据无效 |
| `AUTH_USERNAME_EXISTS` | 409 | 注册用户名已存在 |
| `AUTH_TOKEN_EXPIRED` | 401 | Access Token 已过期 |
| `AUTH_SESSION_INVALID` | 401 | Refresh Session 无效或已撤销 |
| `AUTH_ACCOUNT_UNAVAILABLE` | 401 | 账户不可用 |
| `AUTH_FORBIDDEN` | 403 | 当前用户无权执行操作 |
| `USER_USERNAME_CONFLICT` | 409 | 用户名已存在 |
| `USER_LAST_ADMIN_REQUIRED` | 409 | 操作会导致系统无可用管理员 |

## 6 RAG 问答接口草案

- 方法：`POST`
- 路径：`/api/v1/qa/answer`
- 鉴权：`user`、`admin`
- 状态：HTTP 路由与鉴权已实现；检索器和生成 Provider 尚未接入，当前返回 `503 RAG_RETRIEVAL_UNAVAILABLE`

请求：

```json
{
  "question": "商业银行应如何管理流动性风险？",
  "knowledge_base_ids": ["kb_001"],
  "effective_at": "2026-10-10T00:00:00+08:00",
  "top_k": 8
}
```

`effective_at` 为空时使用请求发生时间。默认只检索在目标时间有效的制度版本；是否允许查询历史失效制度应通过后续独立参数和权限评审，不由提示词临时决定。

成功响应：

```json
{
  "answer": "基于当前检索证据生成的回答。",
  "citations": [
    {
      "label": "S1",
      "document_id": "doc_001",
      "version_id": "ver_001",
      "chunk_id": "chunk_001",
      "title": "制度标题",
      "page_number": 12,
      "article_number": "第二十条",
      "source_url": "https://example.org/policy.pdf"
    }
  ],
  "evidence_support": {
    "score": 0.82,
    "level": "strong",
    "method": "retrieval_evidence_v1",
    "explanation": "表示当前检索证据对回答的支持程度，不是答案正确概率。"
  },
  "warnings": [],
  "trace_id": "请求追踪 ID"
}
```

未检索到有效证据时返回 `200`，提供明确的无依据回答、空引用和 `none` 支持等级，不调用 LLM 猜测答案。所有检索通道不可用时返回 `503 RAG_RETRIEVAL_UNAVAILABLE`；生成 Provider 不可用或返回越界引用时返回 `502 RAG_GENERATION_FAILED`。

只要请求通过校验并返回 `200`，服务端都会为当前用户记录一条问答历史（见 §9.1）；`trace_id` 可作为历史记录与日志的关联标识。

当前不注入 RAG 服务时，问答返回 `503`；不会回退到虚构回答，也不会新增历史记录。具备检索器与生成 Provider 后由后端注入 `RagService`，无需改变前端请求字段。

## 7 知识库接口

知识库是一组制度文档与版本的集合，用于限定问答的检索范围。

知识库对象：

```json
{
  "id": "kb_001",
  "name": "金融监管制度库",
  "description": "面向银行监管政策的公开制度材料",
  "document_count": 12,
  "chunk_count": 1840,
  "created_at": "2026-10-01T02:00:00Z",
  "updated_at": "2026-10-20T08:30:00Z"
}
```

### 7.1 列出知识库

- 方法：`GET`
- 路径：`/api/v1/knowledge-bases`
- 鉴权：`user`、`admin`

查询参数：分页参数（§1.1），另支持 `q` 按名称模糊匹配（可选）。

响应为分页包装，`items` 为知识库对象。普通用户也需要此接口来限定自己的问答范围，因此不对 `user` 限制。

### 7.2 知识库详情

- 方法：`GET`
- 路径：`/api/v1/knowledge-bases/{knowledge_base_id}`
- 鉴权：`user`、`admin`

不存在时返回 `404 KNOWLEDGE_BASE_NOT_FOUND`。

### 7.3 创建知识库

- 方法：`POST`
- 路径：`/api/v1/knowledge-bases`
- 鉴权：`admin`

请求：

```json
{
  "name": "金融监管制度库",
  "description": "面向银行监管政策的公开制度材料"
}
```

约束：`name` 1–80 字符且全局唯一；`description` 可选，不超过 500 字符。

成功返回 `201` 与知识库对象；重名返回 `409 KNOWLEDGE_BASE_NAME_CONFLICT`。

### 7.4 更新知识库

- 方法：`PATCH`
- 路径：`/api/v1/knowledge-bases/{knowledge_base_id}`
- 鉴权：`admin`

`name` 与 `description` 均可选，只更新传入字段。重名返回 `409`。

### 7.5 知识库统计

- 方法：`GET`
- 路径：`/api/v1/knowledge-bases/{knowledge_base_id}/stats`
- 鉴权：`admin`

响应：

```json
{
  "knowledge_base_id": "kb_001",
  "document_count": 12,
  "version_count": 15,
  "chunk_count": 1840,
  "active_version_count": 12,
  "inactive_version_count": 3,
  "embedded_chunk_count": 1800,
  "pending_chunk_count": 40,
  "parse_warning_count": 7,
  "last_ingested_at": "2026-10-20T08:30:00Z"
}
```

用于知识库管理页展示导入健康度；`pending_chunk_count` 表示尚未完成向量化的分块数。

## 8 文档与导入任务接口

### 8.1 上传文档

- 方法：`POST`
- 路径：`/api/v1/documents`
- 鉴权：`admin`
- 内容类型：`multipart/form-data`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 单个文件，上限 **50 MB**（与 Nginx `client_max_body_size` 一致） |
| `knowledge_base_id` | 是 | 归属知识库 |
| `title` | 否 | 缺省取文件名 |
| `tags` | 否 | 可重复传递；每个不超过 32 字符，最多 20 个 |
| `effective_from` | 否 | 带时区 ISO 8601 |
| `effective_to` | 否 | 带时区 ISO 8601，不得早于 `effective_from` |

允许的类型：`application/pdf`、`image/png`、`image/jpeg`、`text/plain`、`text/markdown`、`application/vnd.openxmlformats-officedocument.wordprocessingml.document`。

成功返回 `202`：

```json
{
  "document": { "…文档摘要，字段见 8.2…": "" },
  "ingestion_task": { "…导入任务，字段见 8.6…": "" }
}
```

上传只负责落盘与创建任务；解析、OCR、分段、Embedding 与索引在后台异步完成。**前端应轮询 8.6 获取进度，不要在上传请求上等待解析结果。**

超限返回 `413 DOCUMENT_TOO_LARGE`；类型不支持返回 `415 DOCUMENT_UNSUPPORTED_TYPE`。

### 8.2 文档列表

- 方法：`GET`
- 路径：`/api/v1/documents`
- 鉴权：`user`、`admin`

查询参数：分页参数（§1.1），另支持 `knowledge_base_id`、`policy_status`（`active`/`inactive`/`unknown`）与 `q`（按标题模糊匹配）。

文档摘要对象：

```json
{
  "id": "doc_001",
  "knowledge_base_id": "kb_001",
  "title": "商业银行流动性风险管理办法",
  "file_name": "流动性风险管理办法.pdf",
  "file_size": 2456789,
  "page_count": 32,
  "source_url": "https://example.org/policy.pdf",
  "tags": ["流动性风险", "商业银行"],
  "version_count": 2,
  "current_version": {
    "id": "ver_002",
    "policy_status": "active",
    "effective_from": "2026-07-01T00:00:00Z",
    "effective_to": null
  },
  "created_at": "2026-10-10T02:00:00Z",
  "updated_at": "2026-10-20T08:30:00Z"
}
```

`current_version` 指在服务器当前时间下有效的版本；没有有效版本时为 `null`。

### 8.3 文档详情

- 方法：`GET`
- 路径：`/api/v1/documents/{document_id}`
- 鉴权：`user`、`admin`

在摘要字段基础上增加 `versions` 数组，按 `effective_from` 倒序：

```json
{
  "…": "同 8.2 摘要字段",
  "versions": [
    {
      "id": "ver_002",
      "policy_status": "active",
      "effective_from": "2026-07-01T00:00:00Z",
      "effective_to": null,
      "chunk_count": 620,
      "parse_method": "native",
      "parse_warning_count": 2,
      "created_at": "2026-10-20T08:10:00Z"
    }
  ]
}
```

`parse_method` 取值 `native`（原生文本提取）或 `ocr`，对应术语表中的「解析方式」。

### 8.4 删除文档

- 方法：`DELETE`
- 路径：`/api/v1/documents/{document_id}`
- 鉴权：`admin`

同时删除其全部版本、分块与向量索引，不可恢复。成功返回 `204`。

### 8.5 导入任务列表

- 方法：`GET`
- 路径：`/api/v1/ingestion-tasks`
- 鉴权：`admin`

查询参数：分页参数（§1.1），另支持 `state` 与 `document_id`。

### 8.6 导入任务详情

- 方法：`GET`
- 路径：`/api/v1/ingestion-tasks/{task_id}`
- 鉴权：`admin`

导入任务对象：

```json
{
  "id": "task_001",
  "document_id": "doc_001",
  "version_id": null,
  "state": "processing",
  "stage": "ocr",
  "progress": 0.45,
  "page_total": 32,
  "page_processed": 14,
  "attempt": 1,
  "queued_at": "2026-10-20T08:00:00Z",
  "started_at": "2026-10-20T08:00:05Z",
  "finished_at": null,
  "warnings": ["第 3 页 OCR 置信度较低"],
  "error": null,
  "created_by": "user_001"
}
```

- `state`：`queued`、`processing`、`succeeded`、`failed`、`cancelled`
- `stage`：`received`、`extracting`、`ocr`、`normalizing`、`chunking`、`embedding`、`indexing`、`completed`
- `progress`：0–1 的浮点数；`stage` 为 `completed` 时为 1
- 失败时 `error` 为 `{"error_code": "…", "message": "…"}`

前端按 `state` 与 `stage` 渲染进度，**不硬编码枚举之外的取值**：遇到未知值应退化为通用进度条，避免后端新增阶段时前端报错。

### 8.7 重试导入任务

- 方法：`POST`
- 路径：`/api/v1/ingestion-tasks/{task_id}/retry`
- 鉴权：`admin`

仅 `failed` 状态可重试；成功后 `attempt` 加一并回到 `queued`。其他状态返回 `409 INGESTION_TASK_STATE_CONFLICT`。

## 9 问答历史与收藏

以下接口均标注为「本人」：只能访问当前登录用户自己的数据，越权返回 `403 AUTH_FORBIDDEN`。

### 9.1 问答历史列表

- 方法：`GET`
- 路径：`/api/v1/qa/history`
- 鉴权：本人（`user`、`admin`）

查询参数：分页参数（§1.1），另支持 `q`（按问题模糊匹配）与 `favorited`（`true`/`false`）。

问答记录对象：

```json
{
  "id": "qa_001",
  "question": "商业银行应如何管理流动性风险？",
  "answer": "基于当前检索证据生成的回答。",
  "citations": ["…结构同 §6…"],
  "evidence_support": { "…结构同 §6…": "" },
  "warnings": [],
  "trace_id": "请求追踪 ID",
  "knowledge_base_ids": ["kb_001"],
  "effective_at": "2026-10-10T00:00:00Z",
  "favorited": true,
  "created_at": "2026-10-20T09:12:00Z"
}
```

列表项与详情字段**完全一致**，便于前端复用同一套渲染组件（答案、引用、证据支持度）。

### 9.2 问答详情

- 方法：`GET`
- 路径：`/api/v1/qa/history/{qa_id}`
- 鉴权：本人

不存在返回 `404 QA_RECORD_NOT_FOUND`。

### 9.3 删除问答记录

- 方法：`DELETE`
- 路径：`/api/v1/qa/history/{qa_id}`
- 鉴权：本人

成功返回 `204`。该记录上的收藏一并删除，避免产生悬挂引用。

### 9.4 收藏列表

- 方法：`GET`
- 路径：`/api/v1/favorites`
- 鉴权：本人

查询参数：分页参数（§1.1）。

收藏对象：

```json
{
  "id": "fav_001",
  "qa_id": "qa_001",
  "question": "商业银行应如何管理流动性风险？",
  "answer_excerpt": "回答正文的前 120 个字符…",
  "evidence_support": { "score": 0.82, "level": "strong" },
  "citation_count": 3,
  "created_at": "2026-10-20T09:15:00Z"
}
```

收藏引用问答记录而不复制全文；`answer_excerpt` 由服务端截断生成。

### 9.5 新增收藏

- 方法：`POST`
- 路径：`/api/v1/favorites`
- 鉴权：本人

请求：

```json
{ "qa_id": "qa_001" }
```

成功返回 `201` 与收藏对象；重复收藏返回 `409 FAVORITE_ALREADY_EXISTS`；`qa_id` 不属于本人时返回 `403`。

### 9.6 取消收藏

- 方法：`DELETE`
- 路径：`/api/v1/favorites/{favorite_id}`
- 鉴权：本人

成功返回 `204`；不存在返回 `404 FAVORITE_NOT_FOUND`。

## 10 业务错误码

除 §5 的鉴权错误码外，业务接口使用以下错误码。

| 错误码 | HTTP 状态 | 含义 |
| --- | ---: | --- |
| `INVALID_PAGINATION` | 422 | `page` 或 `page_size` 超出取值范围 |
| `VALIDATION_ERROR` | 422 | 请求体或查询参数校验失败 |
| `KNOWLEDGE_BASE_NOT_FOUND` | 404 | 知识库不存在 |
| `KNOWLEDGE_BASE_NAME_CONFLICT` | 409 | 知识库名称已存在 |
| `DOCUMENT_NOT_FOUND` | 404 | 文档不存在 |
| `DOCUMENT_TOO_LARGE` | 413 | 文件超过 50 MB |
| `DOCUMENT_UNSUPPORTED_TYPE` | 415 | 文件类型不在允许列表 |
| `INGESTION_TASK_NOT_FOUND` | 404 | 导入任务不存在 |
| `INGESTION_TASK_STATE_CONFLICT` | 409 | 任务当前状态不允许该操作 |
| `QA_RECORD_NOT_FOUND` | 404 | 问答记录不存在 |
| `FAVORITE_ALREADY_EXISTS` | 409 | 该问答已被收藏 |
| `FAVORITE_NOT_FOUND` | 404 | 收藏不存在 |
| `RAG_RETRIEVAL_UNAVAILABLE` | 503 | 所有检索通道不可用 |
| `RAG_GENERATION_FAILED` | 502 | 生成 Provider 不可用，或返回越界引用 |

> 请求体校验失败的 `422` 由 FastAPI 默认生成，其 `detail` 为字段级数组。服务端应在返回前统一转换为 `{"error_code": "VALIDATION_ERROR", "message": "…"}` 形式，避免前端依赖框架内部结构（对应 §1「不得依赖异常堆栈」）。
