# RAG 效果与首字延迟优化

## 诊断结论（2026-11-06）

原 50 题报告完成 49 题、失败 1 题，来源命中 48 题、条文命中 35 题。报告展示的 98.0% / 71.4% 以成功题目为分母；以全部 50 题为分母则为 96% / 70%。来源命中本身已经较高，主要短板在条文定位与答案引用选择。

1. **条号元数据缺失**：7 道旧题的完整证据已经在索引中，但条号为空。原文把章标题和第一条正文粘连在同一行，解析器只接受行首或句末后的条号，因此漏识别。正确引用正文也可能无法命中预期条号。
2. **召回与最终上下文之间丢失证据**：修复前 100 题诊断中，向量通道覆盖 92 题完整证据，关键词通道覆盖 70 题，最终 8 条上下文只覆盖 87 题。两通道覆盖有重叠，不能简单相加。RRF 只利用排名，不直接判断语义，关键词高频介绍、新闻访谈和报告片段可能挤出目标条文。
3. **模型引用选择与目标来源不完全一致**：部分问题的多个制度都含相关表述，命中同一文档不代表命中了具体条文。旧报告没有保存当时的完整生成上下文，后续只读重放只能辅助诊断，不能证明历史每次请求的内部排名完全相同。
4. **BGE 查询缺少检索指令**：当前 FastEmbed 对该模型的 query_embed 直接编码原查询，未自动添加中文指令。[BGE 官方模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)建议在短查询检索长正文时添加查询指令，文档端不添加。本轮只调整查询端，不重新生成文档向量。
5. **上下文预算缺陷**：传入条数超过 max_chunks 时错误地在第一条后停止。已由失败测试复现并修复；默认 top_k=8 的原基线未触发，不能把此修复当作基线提升的原因。

443 份文档目前均使用导入默认的 active 状态（status_source=default），并非已逐份核验法律效力。后续应独立校核有效期与废止关系；本轮没有猜测或自动更改制度状态。

## 改动与数据保护

- 识别同一行的章/节标题后条号；普通正文中的“依据第六条”不作为新条文。
- 新增保守条号回填：仅处理缺失条号且能明确归属单条的分块。多条混合或前置正文不猜测；默认预览，--apply 执行。
- 经授权回填 168 个分块条号。完整比对 10,914 条 Milvus 记录，正文、向量、ID、版本及其他字段均不变；MySQL/Milvus 条号一致。未重新 OCR 或全量导入。
- 查询端添加 BGE 官方中文指令；修复上下文条目上限逻辑。
- 用户明确本轮不下载新模型，因此没有接入 Cross-Encoder 或修改模型依赖。未针对固定题目硬编码、改标准答案或调整融合权重。
- 新增 SSE 真实问答路径，沿用同一检索、上下文及最终 JSON/引用校验。前端逐步展示正文，收到 done 后展示最终来源与支持度；失败清除未完成正文。取消/失败不保存成功回答。

## 效果回归

使用当前完整语料，非流式运行现有 100 题；旧 50 题与新增 50 题分别记录，不把已有题目重新宣传为未见过的独立测试集。本轮改动未改变原题与标准结果。

| 指标（全部题目为分母） | 原 50 题历史报告 | 优化后相同 50 题 | 优化后完整 100 题 |
| --- | --- | --- | --- |
| 完成 | 49/50 | 50/50 | 100/100 |
| 来源命中 | 48/50（96%） | 48/50（96%） | 96/100（96%） |
| 条文命中 | 35/50（70%） | 45/50（90%） | 87/100（87%） |

100 题平均字面相似度 40.68%。指标不能替代人工事实核验；LLM 输出和向量近似搜索有波动，单次生成全部成功不代表偶发 JSON 问题已永久消除。条文指标的提升包含元数据纠正，不能全部解释为检索语义能力提高。

元数据回填后的查询指令对照：新增 50 题开发部分的最终上下文来源覆盖从 48/50 到 50/50，条文覆盖从 40/50 到 42/50。原 50 题只作固定回归，没有搜索多组提示词或权重以追分。中途回填尚未完成的诊断文件仅用于过程观察，不作为最终同状态对照。

## 首字与流式验证

后端使用 ChatDeepSeek 的 astream，逐步解码 JSON 内 answer 字符串；完整 JSON、结束原因与引用标签仍在完成时校验。前端 fetch 读取 SSE，Nginx 关闭缓冲。非流式评测接口保留。

首次部署后经 Nginx 的 3 次实测，首段正文分别在 2.033 / 0.375 / 0.960 秒到达，均有多次增量并成功完成。首次略超目标；随后的 5 题实测均达标，首段正文为 1.242 / 0.992 / 0.856 / 0.987 / 0.557 秒，完整回答耗时 1.612–2.051 秒。小样本不能证明所有请求或并发负载下稳定低于 2 秒，远程模型和网络仍可能导致超时。

浏览器端真实登录验证了 `/qa/answer/stream` 请求、生成中可见的部分正文以及最终引用展示；截图位于 `data/processed/qa_stream_partial_2026-11-06.png` 和 `qa_stream_complete_2026-11-06.png`。

## 复现命令

```powershell
# 回填先预览；执行会修改索引元数据，不变更原文件、正文、向量和 ID。
docker compose run --rm --no-deps backend python -m app.workers.backfill_articles
docker compose run --rm --no-deps backend python -m app.workers.backfill_articles --apply

$samplePath = (Resolve-Path data/samples).Path
# 仅检索诊断，不调用收费模型。
docker compose run --rm --no-deps --volume "${samplePath}:/app/data/samples:ro" backend python -m app.workers.diagnose_retrieval
# 真实生成评测会调用 DeepSeek。
docker compose run --rm --no-deps --volume "${samplePath}:/app/data/samples:ro" backend python -m app.workers.evaluate_qa
# 流式计时也调用 DeepSeek，并通过真实接口保存成功问答历史。
docker compose run --rm --no-deps --volume "${samplePath}:/app/data/samples:ro" backend python -m app.workers.benchmark_stream --limit 5
```

回填与导入共用知识库互斥锁，检查 SQL/向量内容与版本后才写入。跨存储没有分布式事务；若中断，可再次执行以补齐未完成条号，不能将成功日志替代最终一致性核验。
