# 文档解析与数据清洗

验证日期：2026-11-24。环境：Windows 11、Python 3.10（仅运行解析函数）、PyMuPDF 1.28.2；Docker Desktop 未启动，未重建容器和 MySQL/Milvus 索引。

## 改动范围

- PDF 改用 PyMuPDF 提取文本块、行坐标和表格；表格行转成 `列 | 列 | 列` 文本，表格区域内的文本块不重复入库。
- 跨页重复的页眉、页脚和页码只在页面上下 12% 区域清理。
- 上一页末段无句末标点、下一页不是新章/条/附件时拼接为同一自然段；页首正文继续沿用上一页条号，遇到新章标题则停止继承。
- OCR 渲染提高到 220 DPI，开启行方向分类；返回平均置信度，低于 0.75 或识别文字过少时写入“需人工复核”告警。
- 文件名命中部门决算、部门预算、财务报表、审计报告等规则时默认跳过；`--include-excluded` 可强制导入。
- 解析版本从 `native-v1` 升为 `native-v2`。

## 全量 PDF 回归

对 `data/raw/` 下 148 份未隔离 PDF 逐文件执行 `parse_document`：

- 有文字层的文件全部完成解析，未出现除“无文字层”以外的异常。
- 无文字层扫描件按预期返回“文件没有可用文字；扫描件需先完成 OCR”，需加 `--ocr` 重新导入。
- 长文档耗时：260 页约 41 秒、246 页约 41 秒、166 页约 22 秒；表格检测是主要增量，仍属离线任务。
- 数据集从 161 份 PDF 减为 148 份，13 份部门决算/预算移到 `data/raw/_excluded/financial_statements/`；TXT 保持 506 份。

## 限制与后续

- 扫描件中的表格仍只按 OCR 文本处理，不还原行列结构；需要 PP-Structure 等版面模型。
- 页眉页脚按“上下边缘重复出现”判断，封面标题或图表标题可能保留；跨页拼接采用保守规则，宁可少拼。
- 未重建 Docker 镜像和索引。要让新规则体现在在线问答，需执行：

```powershell
docker compose up -d --build --wait backend
docker compose run --rm --no-deps backend python -m app.workers.import_documents --rebuild
# 含扫描件的知识库再加 --ocr
docker compose run --rm --no-deps backend python -m app.workers.prune_off_topic
docker compose run --rm --no-deps backend python -m app.workers.prune_off_topic --apply
```

`prune_off_topic` 只删除 MySQL/Milvus 索引，不删除 `data/raw/` 原文件；默认仅预览，`--apply` 才执行。
