# 文档内容去重

## 规则

- 在同一知识库内以文件字节的 SHA-256 判重，不以文件名判重；不做跨格式、空白归一化或语义相似度合并。
- 重复内容直接跳过解析、OCR、Embedding 和索引写入，保留最先导入的文档及引用身份。
- 文件内容变更且没有内容相同的记录时，更新该路径已有文档。若改成另一已入库文档的内容，移除本路径过时的索引后跳过，防止旧内容继续被检索。
- 不同知识库各自保存同内容文档，以保持检索范围独立。
- 原文未变但分块规则、OCR 策略或元数据需要更新时，对保留路径显式使用 `--rebuild`；不同名称的副本不因该参数而再次入库。保留路径会在跳过提示中给出。
- 显式元数据与保留记录冲突时拒绝导入，不默默覆盖制度状态或有效期。应修改保留路径的元数据并重建。
- MySQL 连接级锁覆盖同一知识库的检查与写入，另一导入/清理任务持锁时立即提示重试。SQLite 仅用于单进程自动化测试，不作为并发导入环境。

## 已有索引清理

```powershell
docker compose run --rm --no-deps backend python -m app.workers.deduplicate_documents
docker compose run --rm --no-deps backend python -m app.workers.deduplicate_documents --apply
```

默认只预览。指定 `--apply` 后，每组保留 `updated_at` 最早的记录（相同时按 ID 排序），删除副本的 Milvus 向量、MySQL 分块与文档。原文件和历史回答不删除；历史引用中的被删除分块 ID 不再能直接定位。两类存储没有分布式事务；删除中断时可重新执行清理，恢复索引时应使用保留路径与 `--rebuild`。

## 验证

在后端目录运行 `python -m pytest tests/integration/test_document_deduplication.py`。使用真实 TXT 解析、SQLite 元数据和内存向量替身，不下载模型或调用 LLM。

已验证同名重跑、异名同内容、内容更新、不同知识库、显式元数据更新、重建不引入副本、变化后转为重复的旧索引移除、失败后重试、已有重复清理和测试集别名来源匹配。10 项新增测试通过；完整后端 61 项测试通过。另在真实 MySQL 中验证第二个进程不能取得同一知识库导入锁，释放后可以重新取得。

本地原始数据共有 667 份 TXT/PDF，按字节哈希共有 443 份唯一内容：128 份 PDF、315 份 TXT。用户授权后，已清理首次导入中的 17 份重复索引；清理后保留 128 份 PDF，MySQL 和 Milvus 均为 8,209 个分块。后续恢复导入与评测记录见 [LangChain 迁移验证](LangChain迁移验证.md)。
