# 现有数据批量导入与问答回归

验证日期：2026-10-27。环境：Windows 11、Docker Desktop、本地 Compose。OCR 模型首次运行时下载到独立 Docker 卷；后端镜像构建时复用了本机已有的 BGE 模型缓存。

## 导入与索引

- 首次按原生文字导入 `data/raw/` 下 513 份 TXT 和 161 份 PDF：625 份成功，49 份纯扫描 PDF 因无文字层失败；另有 17 份已导入 PDF 含无文字层页面。
- 修正相同内容不同文件共用分块 ID 的问题后重建索引。分块 ID 现在结合文档 ID，避免 MySQL 主键冲突。
- 接入逐页选择性 OCR，将上述 49 份纯扫描 PDF 与 17 份部分扫描 PDF 列为目标；66/66 份导入成功，文件级失败为 0。部分空白或低质量页面仍保留“OCR 未获得可用文字”告警。
- 最终核对：MySQL 有 674 份文档、21,505 个分块；Milvus 查询得到 21,505 条向量；与 `data/raw/` 中 TXT/PDF 文件比对，缺失 0 份。63 份文档记录了实际 OCR 识别页；全部 674 份文档因缺少 `metadata.json` 使用默认 `active` 状态。
- 轻量 PP-OCRv5 mobile 模型在两页样本上分别约 6.6 秒、6.2 秒；默认中型模型分别约 26 秒、19.5 秒。其中一页去空白文本相似度为 98.3%。这仅是速度与样本文字对比，不是完整 OCR 准确率评测。

## 问答回归

- 通过前端 Nginx `/api` 代理登录后，原截图中的汇率问题返回 200 和制度来源；原先生成无引用时的 `RAG_GENERATION_FAILED` 已改为有明确说明的无依据回答。
- 扫描 PDF 问答：“境内外币支付系统第三期代理结算银行中，哪家银行代理港币？”返回“中国建设银行”，引用扫描通知第 1 页。
- 长篇扫描读本问答：“《金融知识国民读本》全书内容分为哪三部分？”返回与正文一致的三部分，并引用第 6 页。
- Markdown 输出回归：个人账户现金支取限额问题返回 `### 结论`、分项标题、列表和加粗金额，保留独立的 `citations`；短问题也返回 Markdown。无关问题返回 200、空引用和 `none` 支持等级。
- 最终后端镜像执行 `pip check` 无依赖冲突；`python -m unittest discover -s tests/unit -p "test_*.py"` 共 22 项通过。

## 限制

- OCR 识别页已标记需人工复核；复杂版面、表格、低质量扫描和空白页可能有错字或缺字，尚未完成大样本人工准确率评测。
- `data/raw/` 中另有 10 份 DOC、2 份 DOCX、1 份 WPS；按本次用户选择暂不处理，当前导入器不支持这些格式。
- 未提供公开来源链接和制度时效性元数据；答案目前按标题、页码或条文定位，所有文档默认参与有效制度检索，正式使用前需人工核对状态。
- 此次验证了功能链路，尚未测量课程要求的响应时间、准确率与覆盖率指标。
