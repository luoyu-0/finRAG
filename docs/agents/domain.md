# 领域文档

本文件规定工程技能在探索和修改仓库前如何读取领域文档。

## 开始工作前

根据任务范围读取：

- 根目录 `GLOSSARY.md`：领域术语及统一命名。
- 根目录 `GLOSSARY-MAP.md`：仅在未来改为 multi-context 时使用。
- `docs/adr/`：与当前修改范围有关的架构决策记录。

如果这些文件尚不存在，直接继续工作，不把缺失本身视为问题。术语或架构决策真正形成后，再通过 `domain-modeling` 等流程按需创建。

## 当前布局

本仓库采用 single-context：

```text
/
├── GLOSSARY.md
└── docs/
    └── adr/
        ├── 0001-示例决策.md
        └── 0002-示例决策.md
```

示例文件仅用于说明命名方式，不要求预先创建。

## 使用统一术语

Issue 标题、需求说明、代码、测试和架构讨论应优先使用 `GLOSSARY.md` 中定义的术语，避免为同一概念随意引入同义名称。

如果所需概念尚未记录，应先判断它是临时实现细节，还是值得补充到领域模型中的正式概念。

## 处理 ADR 冲突

如果计划或实现与现有 ADR 冲突，应明确指出冲突，不得静默覆盖已有决定。例如：

> 本方案与 ADR-0007 冲突；由于新的资源限制，建议重新评审该决定。
